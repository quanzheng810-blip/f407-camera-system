# RVM 串口图像帧协议 v1

该协议用于在调试阶段通过串口把 STM32F407 图像发送到 Qt 上位机。所有多字节整数采用
大端序，图像帧与普通串口文本可以共用同一串口。上位机通过 `RVMF` Magic 自动区分。

## 帧结构

| 偏移 | 长度 | 字段 | 说明 |
| ---: | ---: | --- | --- |
| 0 | 4 | Magic | ASCII `RVMF`，即 `52 56 4D 46` |
| 4 | 1 | Version | 当前固定为 `1` |
| 5 | 1 | Format | `1` = JPEG，`2` = RGB565-LE |
| 6 | 2 | Width | 图像宽度，大端序 |
| 8 | 2 | Height | 图像高度，大端序 |
| 10 | 4 | Payload length | 图像数据长度，大端序，不超过 8 MiB |
| 14 | 4 | CRC32 | 仅覆盖 Payload，大端序 |
| 18 | N | Payload | JPEG 文件数据或 RGB565 原始像素 |

CRC 使用常见的 CRC-32/ISO-HDLC 参数：多项式反射值 `0xEDB88320`，初始值
`0xFFFFFFFF`，最终异或值 `0xFFFFFFFF`。

## 图像格式

### JPEG（推荐）

Payload 是一张完整 JPEG 文件。帧头宽高必须与 JPEG 解码后的宽高一致。串口带宽有限，
推荐先在 STM32 或摄像头侧生成 JPEG，再发送给上位机。

### RGB565-LE

Payload 必须恰好为 `Width × Height × 2` 字节。每个 16 位 RGB565 像素使用小端字节序，
与 STM32F407 内存中的 `uint16_t` 像素排列一致。

## 接收行为

- 上位机支持帧头与 Payload 分多次到达。
- 支持连续粘连的多个图像帧。
- Magic 之前的数据作为普通串口日志显示。
- 帧头无效、CRC 错误或解码失败时丢弃该帧并继续搜索下一个 Magic。
- JPEG/RGB565 最大分辨率暂定为 `4096 × 4096`，Payload 最大 8 MiB。

## 带宽说明

串口使用 8-N-1 时，每字节约占 10 bit：

| 波特率 | 理论有效载荷 | 20 KiB JPEG 单帧理论时间 |
| ---: | ---: | ---: |
| 115200 | 11.5 KB/s | 约 1.8 秒 |
| 460800 | 46.1 KB/s | 约 0.44 秒 |
| 921600 | 92.2 KB/s | 约 0.22 秒 |
| 1500000 | 150 KB/s | 约 0.14 秒 |
| 2000000 | 200 KB/s | 约 0.10 秒 |

这些是未计入串口驱动、任务调度和协议开销的理想值。串口方案适合调试和低帧率预览，
正式实时视频仍应使用以太网。

## 图像采集命令

当前固件使用 `1500000 / 8-N-1`。上位机发送 ASCII `SNAP\n` 后，固件采集并返回一帧
`320 × 240` JPEG 图像。Payload 从 JPEG SOI `FF D8` 开始，到 EOI `FF D9` 结束，
帧头的 Payload length 和 CRC32 只覆盖这段有效 JPEG 数据。
一次采集或发送尚未结束时再次收到 `SNAP`，固件会在当前
二进制帧结束后输出 `[WARN][SerialImage] busy`，不会把文本插入帧头或 Payload。

上位机发送 `STREAM ON\n` 后，固件进入连续预览模式：每一帧发送完成后自动启动下一次
采集，直到收到 `STREAM OFF\n`。停止命令不会截断正在发送的 RVMF 帧，而是在当前帧完整
发送后停止。`SNAP` 与连续预览共用同一个帧缓冲和发送状态机，预览期间收到 `SNAP`
会返回 busy 提示。当前 320 × 240 JPEG、1.5 Mbps 链路实测约为 4 FPS，实际帧率随
JPEG 大小和画面复杂度变化。

当前 CH340 链路在 2 Mbps 下出现过 CRC 错误，因此默认使用 1.5 Mbps。
如果仍不稳定，可将固件的 `RVM_SERIAL_IMAGE_BAUD_RATE` 改为 `1000000`、`921600` 或 `115200`，
但同一串口两端的波特率必须一致。
